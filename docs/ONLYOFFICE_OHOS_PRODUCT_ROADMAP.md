# ONLYOFFICE 鸿蒙版 —— 产品化路线图

> 版本：2026-09-04（正规化 M1-M5 完成后制定）
> 基座：官方 sdkjs（v9.4.0 `--desktop` 构建）+ 官方 web-apps UI + ArkTS 壳（ArkWeb + native x2t + 文件沙箱）
> 关联：[ONLYOFFICE_OHOS_FEATURE_MATRIX.md](ONLYOFFICE_OHOS_FEATURE_MATRIX.md)（当前功能矩阵）、[ONLYOFFICE_OHOS_PORT_DESIGN.md](ONLYOFFICE_OHOS_PORT_DESIGN.md)（总设计）

## 1. 当前状态定位

**单机演示版。** 核心引擎闭环已通（欢迎页 → 打开 docx/xlsx/pptx → 编辑 → 保存回写 → 新建 → 关闭，全部真机验收），但：

- 文件来源只有沙箱内 3 个 sample，**用户自己的文件进不来**；
- 保存结果只写回沙箱，**出不去**；
- recents 为假数据、无模板、无崩溃恢复、无品牌、无合规声明。

一句话：引擎是产品级的，外壳和数据通道是演示级的。

## 2. 差距清单（P0 / P1 / P2）

### P0 —— 不做就仍是"演示"，不是产品

| # | 功能 | 现状 | 落地要点 |
|---|---|---|---|
| 1 | 真实文件导入 | 仅沙箱 sample | ArkTS 系统文件选择器（FilePicker/uri）→ 拷贝入沙箱 → 现有 x2t 打开链（无需引擎改动） |
| 2 | 保存后导出/分享 | 仅回写沙箱源文件 | Share Kit 分享；另存为系统目录（SaveFilenameDialog 从降级转实现） |
| 3 | 真实文档管理 | recents = 3 个假条目 | `LocalFileRecents` 官方协议已通 → 换成真实目录扫描（沙箱 documents/）；文档列表/重命名/删除/打开所在位置；`LocalFileRemoveRecent` 等配套方法 |
| 4 | 崩溃恢复 + 自动保存 | 无 | 官方 `LocalFileRecovers` 协议 + 周期快照（现有 DOCY 序列化链可直接复用为快照） |
| 5 | 品牌外壳 | logo 点击 404；应用名/图标默认 | `customization.logo` / 拦截 logo 点击；应用名/图标/启动页。**404 必须修** |
| 6 | AGPL 合规 | 无任何许可证声明 | **商用硬约束**：ONLYOFFICE/core/sdkjs 均 AGPL-3.0。应用「关于」页声明许可证 + 源码获取入口；法务确认聚合方式（避免整体传染）。优先度最高 |

### P1 —— 完成度短板（三格式编辑目前约"一半"）

| # | 功能 | 现状/差距 |
|---|---|---|
| 7 | xlsx/pptx 编辑器完整度 | 数据/网格/画布已渲染；cell 顶部工具栏未 init、slide 残余 UI（见 MEMORY v13 记录）——按 docx 同法收尾 + 真机编辑-保存用例 |
| 8 | 本地模板库 | `LocalFileTemplates` 返回 `[]`，欢迎页模板区空白；官方协议现成——沙箱放模板 JSON 即用 |
| 9 | PDF 阅读 / 打印 | PDF 卡片点击无动作、打印入口禁用；PDF 至少先做只读预览（x2t 链够用）；打印需 SystemPrint 评估 |
| 10 | 另存为 / 多格式导出 | SaveFilenameDialog 降级；官方「下载为」面板已有但无宿主；导出 PDF/图片 |
| 11 | 输入法与键盘适配 | 中文 IME / 外接键盘 / 手写笔在 ArkWeb 内体验专项验收 + 软键盘遮挡处理 |

### P2 —— 商用差异化（按目标用户取舍）

| 能力 | 说明 |
|---|---|
| 协同编辑/在线评论 | 需 DocumentServer 服务端 —— **另一个产品线**，建议明确砍掉或单独立项 |
| 宏/插件、拼写词典 | 官方能力，按矩阵 §6 顺序逐项升 |
| 加密文档、数字签名、云存储 | 需 CryptoMode / 签名服务 / OAuth 套件 |
| 多窗口/全屏/旋转锁 | 平板场景高频 |
| 系统"打开方式"注册 | 从文件管理器双击 docx 唤起本 app |
| 大文档性能 | 50MB+ 打开/内存/首启冷启动（163MB rawfile 全量进包） |
| 遥测与崩溃上报 | 商用必配的"故障可知"能力 |

## 3. 建议里程碑

| 里程碑 | 内容 | 通过标准（真机） |
|---|---|---|
| **M7 文件进出**（产品化临界点） | 真实导入 + 导出/分享 + recents 换真数据 + 文档管理 | 从系统文件选择器打开用户 docx → 编辑 → 分享出去收到正确文件；recents 为真实文档历史 |
| **M8 可靠性** | 崩溃恢复 / 自动保存策略 / 大文档性能 | 杀进程重启 → 恢复未保存编辑；50MB docx 可打开编辑 |
| **M9 外壳** | 品牌（logo/图标/标题）+ 设置页（语言/版本/关于）+ AGPL 声明 + 模板库 | logo 不再 404；关于页含许可证声明；模板卡片可新建 |
| 穿插 | xlsx/pptx 工具栏完整度 | cell/slide 编辑-保存真机用例通过 |

## 4. 待决策范围项

- **协同/云是否在目标范围**：决定是否联 DocumentServer（另一产品线）。若纯本地单机，本路线图即终版。

## 5. 与既有机制的关系

- 所有 P0 项的**引擎侧均零改动**：文件进/出/恢复/模板/recents 全部走官方 `window.AscDesktopEditor` 桥协议（LocalFile* 家族），只改 ArkTS 壳层的沙箱与系统调用；
- 保存链（DOCY;v10 → x2t → 落盘）可扩展为快照/导出/另存为的公共底座；
- 品牌项（logo 404）已登记 FEATURE_MATRIX §4/FEATURE_MATRIX 降级表，属"官方已实现、本机未接"类，接续路径明确。
